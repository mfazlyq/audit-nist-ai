# Architecture and implementation notes

## Current pipeline

1. **Input:** the user supplies a NIST reference PDF and a campus SOP/policy PDF.
2. **Extraction:** LangChain's PDF loader extracts page text.
3. **Chunking:** RecursiveCharacterTextSplitter creates 1,200-character chunks with 200-character overlap.
4. **Embedding and indexing:** Hugging Face all-MiniLM-L6-v2 creates embeddings; Chroma stores them for retrieval.
5. **Retrieval:** the prototype retrieves up to 15 chunks using a broad cybersecurity-gap query.
6. **Generation:** a Groq-hosted language model drafts prioritized findings using the retrieved context.
7. **Parsing:** audit_utils.parse_nist_findings validates the pillar and NIST CSF 2.0 control identifier before displaying a row.
8. **Output:** Streamlit displays the findings and a radar chart, and offers CSV and PDF downloads.

## Important design boundaries

- The model output is a draft, not an authoritative compliance determination.
- The current retrieval query is broad and does not guarantee complete coverage of every NIST outcome.
- The current ranking is generated by the LLM; it is not a formally calibrated risk score.
- The parser validates allowed function names and control-ID formats, but it does not prove that a cited control is supported by the uploaded evidence.
- Reviewers should retain source-page references and independently verify each gap before using the report.

## Recommended next engineering steps

1. Attach page-level source references to every generated finding.
2. Replace a single broad retrieval query with outcome-level retrieval across the selected NIST CSF functions.
3. Use a structured output schema and validate findings before rendering.
4. Separate extraction, retrieval, generation, validation, and reporting into testable modules.
5. Add integration tests with small, synthetic PDF fixtures.
6. Add a documented data-retention policy and explicit confirmation before sending institutional text to an external LLM provider.
